# 真实远征平衡与经营节奏报告

版本补充：此报告的90局数值来自即时出生交互改版前的领取路径。新版`run.ts`保留该路径，三策略各复跑`campaign-v1-001`后，整局记录与这里对应的三局逐字段相同；见`artifacts/balance/auto-birth-legacy-verification.json`。这不是新版自动出生UI的90局验收，后者另行验证。

当前最终样本为`artifacts/balance/shipping-30.json`：三种合法经营策略各30个种子，共90局。均衡30局、毒疗30局、骑兵29局完成全部36波；零API/策略错误。结论是三种构筑均可通关，而且熟练自动策略下压力偏低。后期仍有现金取舍，但有效新兵频率下降，部分高成型样本会长时间重复吸收或遣散。

## 版本与复现

- 生成时间：`2026-10-09T20:01:37.083Z`；战斗源码SHA-256：`3c41a7aa855d564d5a001c1d3bb3b8ca7befffe4fde535e9140a820620575997`。
- JSON的`sourcesUnchangedDuringRun = true`，记录10份源码/内容（含统计成长函数与RNG）的运行前SHA-256并在结束复核。运行中变更源码或出现策略错误会返回非零退出码。
- 样本是`campaign-v1-000`至`campaign-v1-029`。三策略使用同一组编号，各自选择初始军团、分支、权重、遗物和路线。
- 最终90局开启`--roundtrip`：6967次阶段存档重载、3216次战斗中途快照恢复，覆盖全部3216场实际战斗。独立关闭重载重跑`campaign-v1-001`三策略后，除重载计数外，全部经营/战斗记录逐字段相等；证据为`shipping-save-verification.json`。
- 当前`policyVersion = 2`。旧策略有时会把已上阵的高阶兵作为新低阶兵的换壳材料；行为合法，却造成无意义的UID/专精重选，并夸大阵容变化。新策略只将招募暂存中的新高阶身体用于已有军团，保持原兵身份。
- `release-30.json`、`final-30.json`及`cadence-30.json`是旧引擎/旧策略或采纳新遭遇前的历史样本。不能用它们与本样本的胜率差异，推断某一条战斗修复带来了等量难度改变。
- 每次状态修改都经`run.ts`公开动作；每次阶段推进检查`validateRun`。没有编辑钱、HP、军队、盘面、掉落或战斗结果，没有失败后更换种子。
- 普通快速模式使用正式`simulateBattle`；本轮为验证每场战斗的存档恢复，全部使用同一引擎的`createBattle/stepBattle`路径，在3.25秒处载入快照继续。引擎固定步0.05秒；随机盘面干预的估值使用独立固定采样器，不读取游戏未来RNG。

```sh
npm run balance -- --roundtrip --seeds 30 --strategy all --out artifacts/balance/shipping-30.json
npm run balance -- --seeds 30 --strategy plague --prefix campaign-v1 --out artifacts/balance/plague-30.json
npm run balance -- --seeds 1 --offset 1 --strategy all --out artifacts/balance/shipping-no-reload-3.json
```

`--seeds`为每策略样本数；`--strategy`支持`all / balanced / plague / cavalry`；`--offset`是起始编号；`--prefix`控制种子前缀；`--roundtrip`开启阶段重载和战斗快照恢复验证。须使用样本JSON记录的同一源码版本复现。

## 经营功能审计与修复

- 地图：1000种子修复前有993张包含永久不可达绘制节点，共6610个；修复后全部57节点可达，非Boss仍只连接相邻下一层的1–2条边。证据：`map-audit-1000.json`。地图随机序列改变，不能把前后胜率差直接归因于连接修复。
- 遗物：库存与装备槽独立，满槽奖励不软锁。机器在节点首次拉杆后锁定；军团遗物在战斗中锁定。M13现在只让实际存活上阵的新兵占用“两名”配额，后备/被吸收候选不会抢掉后续上阵兵的盾；吸收和换壳不继承候选buff。
- 干预与道具：总计两次干预、每来源一次，费用/道具在成功交易时支付。I01/I02只在实际拉杆时消耗；若直接开战会自动取消未执行预备，保留库存并释放战内道具额度。
- 黑市：刷新4/7/10后封顶；旧商品不能重买，刷新不出售已拥有遗物。背包满或错误替换目标导致购买失败时，钱、商品售出标记和RNG均不变。
- 奖励与事件：每波、每节点奖励不可重放；八事件每次只结算一次，离开后不能回头重入。单局最多6个事件访问，池中8个事件无需重复。
- 容量与成长：上阵4→8须逐级付款，后备8。暂存必须显式解决后开战；吸收加训练经验，换壳只允许同族严格更高出生阶，保留较高XP，不因Lv4或Lv8自动升R阶。
- 存档：补查缺失统计/计数/奖励/库存、未知敌人和损坏战斗快照，避免载入成功后才崩溃。真实战斗中途存档、加载、继续推进，序列化后的RNG、位置、冷却和效果逐字段一致。
- 经营测试37/37及全局TypeScript检查通过，含100种子遭遇变体/预算/预览一致性、逐阶段跨章存档与Boss奖励防重放。测试中的战斗结果夹具只服务经营状态测试；本报告90局使用真实引擎。

## 建议与证据边界

已通过上述有限遭遇和目标规则提高可读应对压力；接下来应在真人实机中检验敌情提示是否促使换位、换人或遗物应对。保留高阶高等级大奖的强势回报，不因一局幸运成型样本破坏已约定的线数/出生阶规则。

不要先削经济或增加经营步骤来拖长30分钟：现金已经约束扩容，削钱更可能让低效追抽者卡在少兵位；新增无收益操作会放大重复感。真人计时、操作理解和流派可读性应由浏览器E2E单独验证。本轮只采用明确披露的遭遇替换和目标选择规则，未修改兵种HP/攻击模板或经济数值；后续任何数值或战斗行为变更，都应再次使用同一组种子生成最终报告。
